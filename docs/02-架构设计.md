# 02 架构设计

## 1. 总览（分层）

```
            ┌─────────────────────────────────────────────┐
 输入 ──────▶│  respond(messages, tools, policy)           │
            │                                             │
            │  1) 提示词层  _build_system_prompt(policy)    │
            │     → system = 政策 + 8规则 + 工作流 + 合同   │
            │                                             │
            │  2) 模型层   interview_sdk.chat(...)          │
            │     （平台代理 / 本地 OpenAI·DeepSeek）        │
            │                                             │
            │  3) 护栏层  _enforce(result, messages, tools) │
            │     → 鉴权 / 写前状态 / 确认新鲜度 / 必填 /    │
            │        单工具 / 形状 校验                     │
            │                                             │
            │  4) 输出    {"content":...} 或 {"tool_call"}  │
            └─────────────────────────────────────────────┘
                              │
                              ▼
            平台工具执行器（考试提供，不在本仓库）
            locate / read_profile / read_reservation /
            inspect_family / compute / change_asset
```

## 2. 关键设计决策

1. **为什么加"护栏层"？**
   模型在考试环境里不可控（无外网、固定代理），且其输出可能偶尔不守规则。
   把"安全相关"的判断从"指望模型自觉"改为"代码确定性校验"，直接吃下 15% 安全分，
   并规避"意外/过期写"的额外重罚。

2. **为什么必须通用、不能写死练习数据？**
   正式题目每次重新生成客户/设备/标识符。`agent.py` 里**没有任何** Mara Voss、
   RS-BC348019D 之类的硬编码；所有推理都来自 `tools` 返回的证据。

3. **为什么用"标记词"检测确认与提案？**
   无状态环境下，确认状态只能从 `messages` 文本推断。用"助理提案（含 change/replace…）
   + 其后出现客户确认词（yes/confirm/proceed…）"来定义"新鲜确认"，既支持单改也支持
   批量（一次计划确认覆盖多单），且客户改主意（新提案在确认之后）会自动使旧确认失效。

4. **依赖注入便于测试**：模型调用集中在 `chat`，测试时可替换为 mock，实现离线 E2E。

## 3. 状态重建策略（无状态核心）

每轮 `respond` 从 `messages` 解析：
- **是否已鉴权**：扫描 `role=="tool"` 的结果，找 `locate_member` 成功返回的 `MB-...` id。
- **预约当前状态/资产**：扫描工具结果里 `reservation_id` 匹配的字典，取 `status` 与 `assets`。
- **确认是否新鲜**：扫描助理消息里的"提案标记"与用户消息里的"确认标记"，比较下标。

## 4. 模块职责（见 SDD）
- `agent.py::respond` —— 入口，拼 system + 调 chat + 过护栏。
- `agent.py::_build_system_prompt` —— 注入政策与规则。
- `agent.py::_enforce` —— 确定性护栏。
- `agent.py::_is_authenticated` / `_confirmation_present` / `_find_reservation` —— 状态解析。
- `interview_sdk.py::chat` —— 模型客户端（平台代理 / 本地 provider），**不改动**。
- `practice_runner.py` / `mock_runner.py` —— 本地/离线执行器，**不改动**（mock 仅供本地验证）。
