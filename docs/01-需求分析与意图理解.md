# 01 需求分析与意图理解

## 1. 题目到底要什么（意图理解）

这是 **MetaNovas 的 AI 应用工程师笔试**。核心任务：实现一个**事务型客服 Agent**——
在一个"受限、无外网、数据随机"的环境里，根据「客户对话 + 工具 Schema + 政策文本」，
正确完成客户支持任务（典型如：设备预约改单、批量改单、拒绝越权、处理客户改主意）。

你提交的只有一个文件 `agent.py`，里面必须实现：

```python
def respond(messages: list[dict], tools: list[dict], policy: str) -> dict:
    ...
```

平台会**反复调用** `respond`，每次都传「到目前为止的完整对话」。你的函数每次只能做一件事：
要么**对客户说一句话** `{"content": "..."}`，要么**调用一个工具** `{"tool_call": {"name":..., "arguments":...}}`。
最后平台根据工具调用是否正确、是否守规则自动评分。

## 2. 技术难点（为什么这道题不简单）

| # | 难点 | 对实现的影响 |
|---|---|---|
| 1 | **完全无状态**：每次只给 transcript，不能依赖全局变量 | 必须每轮从 `messages` 重建"意图/已完成/待办/确认状态" |
| 2 | **模型不可控**：考试强制走平台代理、无外网，不能换模型、不能联网查答案 | 能控制的只有「提示词」+「对模型输出的确定性护栏」 |
| 3 | **政策极严**：鉴权、一次确认一次写、不许瞎编、约束全用上、批量、改主意 | 任何一步违规都扣分，越权写重罚 |
| 4 | **数据随机**：每次题目/记录/标识符都重新生成 | `agent.py` 必须**通用**，绝不能把练习数据写死 |
| 5 | **安全占分高**：Harness discipline & policy safety 占 15%，且"意外/过期写"额外重罚 | 护栏不是锦上添花，是保命分 |

## 3. 需求分析

### 3.1 功能需求
- 实现 `respond(messages, tools, policy)`，严格返回两种形状之一。
- 正确选择 6 个工具并给出**精确参数**（见接口文档）。
- 完整走通：身份验证 → 读档案 → 读预约 → 查设备家族 → 算费差 → 提案+要确认 → 确认后写。
- 批量请求：先列逐单计划，拿确认，逐单执行，最后汇报。
- 客户改主意：立即丢弃旧计划，从当前记录重算。
- 越权/不合规请求：用已验证事实拒绝。

### 3.2 非功能需求
- 单文件、**UTF-8**、**≤150KB**。
- **零外部依赖**（只用标准库 + 平台提供的 `interview_sdk`）。
- 无网络访问、无文件系统副作用、确定性护栏优先于"模型自觉"。

### 3.3 八条规则 → 实现策略映射
| 官方规则 | 实现策略 |
|---|---|
| 1 先鉴权再读隐私 | `_is_authenticated` 门：无 `locate_member` 成功结果则私读被拦 |
| 2 每回合最多一工具 | 模型返回单 `tool_call`；护栏不再追加 |
| 3 写前精确说明+新鲜确认 | `_confirmation_present` 门：确认必须在"最近提案"之后 |
| 4 不许瞎编 | 提示词强约束 + 所有数值来自工具结果 |
| 5 约束全用上、选真最优 | 提示词工作流 + 证据校验 |
| 6 越权拒绝 | 写前状态校验（非 awaiting_collection 直接拒） |
| 7 改主意丢弃旧计划 | 新提案使旧确认失效（提案在确认之后 → 未授权） |
| 8 批量列计划再执行 | 提示词 + 确认门支持"一次计划确认覆盖多单" |

### 3.4 评分权重 → 投入重点
意图识别 20% / 工具与参数 20% / 计划与执行 20% / 证据判断 15% / 表达 10% / **安全纪律 15%**。
安全纪律与"工具参数精确"是性价比最高的加固点（确定性护栏直接覆盖）。

## 4. 范围与边界
- **范围内**：`agent.py` 的逻辑（提示词 + 护栏）。
- **范围外（考试平台提供，不在我们代码里）**：工具执行器、`messages` 的拼接与注入、确认话术注入、随机题目生成。
- **练习包内可改的只有 `agent.py`**；`interview_sdk.py` / `practice_runner.py` 不应改动（考试时用平台版本）。
