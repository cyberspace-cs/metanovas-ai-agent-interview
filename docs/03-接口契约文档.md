# 03 接口契约文档

## 1. 主入口契约

```python
def respond(messages: list[dict], tools: list[dict], policy: str) -> dict:
    ...
```

- `messages`：完整对话历史（`user` / `assistant` / `tool`）。**每次调用都包含全部历史**。
- `tools`：当前可用的工具 Schema（OpenAI function-tool 格式）。
- `policy`：政策文本（考试时为正式政策，结构与 `practice_policy.md` 一致）。

### 返回形状（二选一，绝不能同回合既说话又调工具）
```json
{ "content": "对客户说的话" }
```
```json
{ "tool_call": { "name": "工具名", "arguments": { "参数": "值" } } }
```

## 2. 工具 Schema 一览（练习包 6 个，正式题同构）

| 工具 | 用途 | 必填参数 |
|---|---|---|
| `locate_member` | 用全名+6位码验证并定位会员 | `full_name`, `member_code` |
| `read_member_profile` | 读已验证会员的积分与预约引用 | `member_id` |
| `read_reservation` | 读某预约的状态与已预留资产 | `reservation_id` |
| `inspect_asset_family` | 列某设备家族的规格/费用/可用性 | `family_id` |
| `compute_amount` | 计算费用算术（如 "53.5 - 39.5"） | `expression` |
| `change_reserved_asset` | **写操作**：在 awaiting_collection 下替换资产 | `reservation_id`, `old_asset_id`, `new_asset_id`, `credit_id` |

> 正式题可能微调工具名/字段，但**契约形态不变**：护栏层按"名称启发式 + 必填参数校验"
> 自适应，不写死具体名字。

## 3. 政策要点（来自 practice_policy.md，正式政策同构）
- 验证会员（全名+6位码）后才能读档案/预约；只读写属于该会员的记录。
- 工具结果是"真相来源"：状态、可用性、规格、费用、余额都以它为准。
- 多约束请求：先逐条评估再选；含最小/最大时要比较所有合格项取**真正最优**；不跨家族替换。
- 只有 `awaiting_collection` 的预约才能改资产；改前说明「预约/当前项/目标项/费差/资金来源」，
  取得**新鲜、明确**的该次变更确认（一次确认只授权一次写）。
- 客户改请求则丢弃过时计划，按当前记录重算；未成功写入不得谎报完成。

## 4. 护栏返回示例（被拦截时不调工具，改为对客户说明）

```json

```
